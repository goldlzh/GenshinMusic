# GenshinMusic：原神 MIDI 键盘自动演奏工具

这是一个仅适用于 Windows 的原神乐器辅助工具。程序读取 MIDI 文件，将其中的音符、节拍和速度变化转换成原神乐器界面的 21 个键盘按键，并按 MIDI 时间轴自动触发按键。

程序本身不合成或播放音频，也不修改游戏文件；它的输出是发往当前前台窗口的键盘输入。因此，正式播放前需要先在原神中装备并打开可用键盘演奏的乐器界面。

**仓库和发布包均不包含 MIDI 文件、个人标签或歌曲记忆。** 请自行将 MIDI 放入 `songs` 目录；首次运行会生成本机配置。Windows 可运行程序从仓库的 **Releases** 下载，源码安装见下方说明。

## 主要功能

- 图形界面搜索、解析和播放 `songs` 目录中的 `.mid` / `.midi` 文件。
- USB MIDI 电子琴实时演奏：设备选择、移调、八度折叠、跟随松键与延音踏板、即插即弹。
- 识别 MIDI 速度变化，将 tick 时间准确换算成秒。
- 四种音长模式：固定短按、原谱音长、旋律长音、和弦长音；支持可选的 MIDI 延音踏板。
- 实时演奏可视化：五线谱时值/长条谱、21 键高亮、红色不可奏音符、长音保持和短音触发提示，可打开独立置顶窗口。
- 按 MIDI 通道筛选乐器，自动保留音符数最多的 3 个通道。
- 自动识别主旋律，也可手动指定主旋律音轨。
- 在 `-12` 到 `+12` 个半音中分别计算开启/关闭八度折叠的转调建议，优先保留主旋律。
- 支持只弹主旋律、屏蔽密集扫音、八度折叠和 `0.5x`～`2.0x` 变速。
- 支持和弦、近同时音、暂停、停止、进度跳转、上一曲、下一曲、顺序播放、单曲循环和随机播放。
- 支持歌曲进度标签；标签和全局快捷键保存在 `song_labels.json`。
- 每首歌自动记住上次起播配置和起播标签，支持优先级更高的手动记忆。
- 使用 Windows 全局热键，在游戏处于前台时也能控制播放或插入标签。

## 工作原理

### USB MIDI 电子琴实时演奏

主窗口新增“USB MIDI 电子琴”页。连接支持 USB MIDI 的电子琴后点击“刷新设备”，选择输入端口，再点击“连接并开始（5 秒准备）”，切回原神乐器界面即可弹奏。支持 Windows 已识别的 MIDI 输入设备，不需要额外安装 Python MIDI 驱动库。

默认跟随电子琴的按下／松开状态，勾选“跟随延音踏板”时也处理 CC64；关闭“跟随松键”则固定短按 40 ms。力度不改变游戏输入。移调范围为 −48～+48 半音，可独立开关八度折叠；黑键和关闭折叠后的超范围音会跳过。设置修改在下一次连接生效。

“合并同时按下的音符”默认开启，区间默认 **30 ms**，可设置为 **0～200 ms 的整数**。从一组首个可演奏音符的到达时间起计时，窗口内的起音统一发出，不因新音符继续延长窗口。已有长音时仍可收集新和弦，松键与踏板独立处理，不会等合并窗口到期。区间越大，起音等待越长；设为 0 或取消勾选即可关闭。极短触键在等待期间松开时仍输出至少 40 ms，避免漏音。此项只影响 USB MIDI 实时输入，不改变歌曲的组内延迟或速度规则。

“即插即弹”会在原神处于前台、电子琴已接入且没有歌曲播放时自动连接。实时按键只在原神处于前台时输出；切换窗口、暂停、停止、断开设备或退出程序都会释放琴键。回到游戏后按新音继续，后台按过的音不会补发。点击停止或启动 MIDI 歌曲会暂时停用自动连接，重新连接或重新勾选即插即弹即可恢复。

实时输入和 MIDI 文件播放共用键盘所有权锁。多通道或八度折叠后落到同键的音分别记住所有者，松开其中一个来源不会提前松掉其他仍保持的音。电子琴页显示当前实际输出按键；原有谱面可视化用于 MIDI 文件播放。

输入通过 Windows WinMM MIDI 回调进入队列，由单一工作线程处理，回调本身不操作键盘。异常或输入队列溢出时结束会话并释放游戏琴键。

完整处理链路如下：

```text
MIDI 文件
  → 读取 tempo / note_on / note_off / program_change / CC64
  → 配对起音与关音，tick 按速度图换算成绝对起止秒数
  → 排除鼓组并按通道筛选
  → 标记主旋律、检测扫音
  → 移调和八度折叠
  → MIDI 音高映射为原神 21 键
  → 按音长模式确定每音时值，整体变速
  → 同时同键去重、同键重触发、真正空白压缩
  → 统一调度全部按下与松开事件
  → pydirectinput 发送 keyDown / keyUp
```

### 1. 读取 MIDI 时间轴

`mido` 读取 MIDI 后，程序先合并各音轨中的 `set_tempo` 消息，建立“绝对 tick → 每拍微秒数”的速度图。随后累计各音轨的 delta time，按通道、音高配对 `note_on` 与 `note_off`；同轨道优先，跨轨关音及重复同音采用队列配对。起止 tick 分别换算成秒，跨越速度变化的长音也能得到正确时值。

`note_on` 且力度大于 0 表示起音；力度为 0 的 `note_on` 也按关音处理。力度数值不控制游戏按键。缺少关音消息的音符回退到 250 ms，并在日志中提示。MIDI 的鼓组通道会被排除；代码中的 `DRUM_CHANNEL = 9` 对应通常所说的 MIDI 第 10 通道。

### 2. 筛选乐器和识别主旋律

程序通过 `program_change` 统计每个通道使用的 GM 音色与音符数。解析一首歌时，界面默认勾选音符数最多的 3 个非鼓通道，用户可以自行增减。

主旋律按以下规则标记：

- 多个含音符音轨：默认选择平均音高最高的音轨作为主旋律，也可在界面手动指定。
- 单个含音符音轨：按 15 ms 窗口分组，将窗口内最高音标为主旋律（天际线法）。

“只弹主旋律”会在后续映射前删除所有伴奏音符。自动判断并不理解乐曲语义，复杂编曲出现误判时应手动选择音轨或调整通道。

### 3. 移调、音域与 21 键映射

原神的三排按键对应 3 个八度的自然音：

| 音区 | MIDI 音高 | 游戏按键 |
| --- | --- | --- |
| 低音区 | 48, 50, 52, 53, 55, 57, 59 | `Z X C V B N M` |
| 中音区 | 60, 62, 64, 65, 67, 69, 71 | `A S D F G H J` |
| 高音区 | 72, 74, 76, 77, 79, 81, 83 | `Q W E R T Y U` |

这些音高是三个八度的 C 大调自然音。升降音（黑键）没有直接对应按键。

自动移调会对开启/关闭折叠分别尝试 `-12`～`+12` 个半音。评分依次比较：主旋律可映射数量、旋律音程变化、主旋律同键重叠、伴奏可映射数量、折叠八度总数、移调绝对值。报告同时显示两种建议；切换“八度折叠”会采用对应建议值，之后仍可手动输入转调。恢复歌曲记忆时保留已保存的手动转调值。应用移调后：

- 关闭“八度折叠”时，超出 48～83 或不是自然音的音符会被丢弃。
- 开启“八度折叠”时，过高或过低的音会按八度升降到 21 键音域内。
- 八度折叠不会改变音名，所以升降音仍无法映射，最终会被丢弃。

因此，标有“原琴”“原神适配”“C 调”或本身主要使用自然音的 MIDI，通常效果更好。

### 4. 音长模式、扫音与按键整理

| 模式 | 行为 |
| --- | --- |
| 固定短按 | 每个音保持约 40 ms，适合与旧版本对照。 |
| 原谱音长 | 全部音符按 MIDI 时值保持；新歌曲默认使用此模式。 |
| 旋律长音 | 主旋律按 MIDI 时值保持，伴奏固定短按。 |
| 和弦长音 | 只有近乎同时起音的和弦伴奏按 MIDI 时值保持，主旋律与单音伴奏固定短按。 |

“和弦长音”要求原速 15 ms 起音窗口内至少有两个不同的可映射伴奏键；分组以首个起音为界，不把连续琶音串成长和弦。主旋律不计入这个数量，重复同键或八度折叠后落到同键的音只算一个键；无法映射的音不会帮助单音伴奏获得长音资格。同一时刻与主旋律共用琴键时优先让该键短按。和弦各音保持自己的起音偏移及原谱音长，变速不会改变哪些音被识别为和弦；这项判定独立于报告中的 80 ms 分组统计。

“跟随 MIDI 延音踏板”默认关闭。开启后，长音部分会将 CC64 踏板保持期间的关音延后至踏板释放；固定短按部分不受影响。没有踏板释放消息时以文件结束为界。正常长音不设固定秒数上限。

默认会屏蔽可能由滑奏或扫音产生的密集音列。当前判定条件是：连续至少 6 个音、相邻间隔不超过 60 ms、音高同方向变化且每步不超过 2 个半音。

映射为键盘按键后，程序还会进行以下整理：

- 同时发生的同键音符合并，保留最晚松键时间和主旋律标记。
- 不同音符保持各自的起音与松键时间；同一个和弦内也可以有不同音长。
- 同键再次起音前截短前音，保留 10 ms 松键间隔，再次按下；旧关音不会松掉新音。
- 折叠后落到相同按键的伴奏，不打断正在持续的主旋律。
- 不再因处于同一个 80 ms 分组而删除先后发生的同键音，也不再应用旧版 80 ms 伴奏冷却和分组节奏平滑。
- 首音时间归零；在同键冲突处理后，仅将所有按键都已释放且超过 1 秒的谱面空白压缩为 1 秒。长音及踏板保持不视为空白；变速时此空白也同比缩放。

压缩空白会改变 MIDI 的原始总时长。最短按压目标为 40 ms；如与下一次同键起音冲突，优先缩短前音以守住下一拍。连 10 ms 重触发间隔也容纳不下的极密同键音会按主旋律优先进行取舍。

### 5. 定时与键盘输入

播放线程以 `time.perf_counter()` 作为单调高精度时钟。每个音的绝对起音时间、组内偏移和原谱音长都除以速度倍率；固定短按的 40 ms 和重触发所需的 10 ms 使用真实时间，不随速度缩短。

全部按下和松开事件由一个线程调度，不再让每个音各自创建睡眠线程。歌曲总时长包含最后一次松键。暂停、停止或跳转时释放全部琴键；继续和跳转后重新建立时间基准。**从中途起播或改变播放位置时，只演奏该位置及之后起音的音符**，之前开始的长音即使延长线经过新位置，也不会补按。普通暂停后继续且未改变位置时，仅接回暂停前实际按住的音符。不同播放实例共用键盘所有权锁，切歌时旧实例必须先释放琴键。

`pydirectinput` 使用更适合游戏识别的 Windows 输入方式。游戏需要保持在乐器演奏界面并接收键盘焦点；倒计时期间应切回游戏。

### 6. 实时演奏可视化

解析歌曲后，主窗口的“演奏可视化”页会显示当前配置生成的谱面；原来的文本报告保留在“解析报告 / 日志”页。可奏部分使用经过通道筛选、转调、八度折叠、音长模式、变速与同键冲突处理后的最终按键时间轴，另外保留无法映射的音符供观察。

- **五线谱时值**：用高、低音两组五线表示音高，音符后方的横线表示按压时长。横轴按实际秒数展开，便于观察长音；不是按小节排版的传统乐谱。
- **长条谱**：每个按键占一行，横条长度表示按压时长，适合比较和弦各音的松开时间。
- **21 键状态**：按游戏的高、中、低三排排列，直接显示当前按下与未按下的键。
- **时间窗**：可选择 4、8、12 秒。金色竖线表示当前播放位置，右侧为即将演奏的音符。

颜色含义：绿色为播放器当前保持的按键，蓝色为待演奏的主旋律，紫色为待演奏的伴奏，灰色为已经释放或已经跳过的音符，包括起点之前长音的延长线；金边表示最近 180 ms 内触发过的短音，避免快速按下、松开在刷新间隔中不易看清。金边不表示还在按住。

**红色表示当前配置下无法演奏的音符**：关闭折叠时超出 C3～B5 的音，以及没有对应琴键的升降音。红色音符显示音名，悬停可查看原因和时间；经过播放位置后变为暗红色。五线谱中使用空心虚线标记，以便与相同线位的可奏长音区分。音域会自动扩展，较亮的背景区域表示 21 键音域。开启八度折叠后能映射成功的音符恢复正常显示，升降音仍标红；红色数量随转调和折叠设置重新计算。

红色仅针对经过通道、“只弹主旋律”和“屏蔽扫音”筛选后仍无法映射的音符。这些标记不发送按键，也不改变播放器总时长或原有演奏节奏。它们共用演奏的时间变换，位于被压缩间奏中的红音也同比放入缩短后的间奏。

将鼠标放在谱面上可直接用**滚轮浏览时间轴：向上滚往前，向下滚往后**，每格移动当前时间窗的 1/10；按住 **Shift** 滚动则再细分为 1/10。例如 8 秒时间窗中分别移动约 0.8 秒和 0.08 秒。谱面下方的横向滚动条也可浏览整段时间轴，浏览时自动取消“跟随演奏”；重新勾选即可回到播放位置。浏览不影响实际播放或起播点。首个可奏音之前被跳过的红音位于负时间，可向左浏览；最后一个可奏音之后的红音可向右浏览。即使当前配置没有可奏音符，也能预览红音，但不能启动演奏。

**左键点击谱面只调整进度，开始演奏需手动点击“播放/继续”**。点击音头或长条左端时会对齐该音的起音；点击延长线则使用点击处的时间，不会倒回旧音头。正在演奏时点击会暂停并定位，原本暂停的仍保持暂停；倒计时中点击会取消自动起播并保留所选位置。主窗口和独立窗口均遵循这一规则。手动点击“播放”后仍保留 5 秒切回游戏的倒计时。

**拖动进度条期间，主窗口与独立窗口都会实时预览所选位置**，时间显示精确到毫秒，播放和暂停状态下均可使用。松开鼠标才提交实际跳转；暂停中拖动后仍保持暂停，可确认位置后再继续。后台旧进度不会将刚选好的位置拉回去。倒计时中拖动进度条同样会更新实际起播点。

正常播放时，绿色高亮来自播放线程发布的实际按键状态，不是根据时间轴推测。暂停、停止会清空高亮；普通继续时仅恢复之前实际按住的音，跳转后等待新位置之后的起音。拖动预览期间不显示实际按键高亮，松手并完成定位后恢复播放器状态。未播放时拖动只预览谱面，不发送按键。播放/倒计时期间修改演奏参数，正在显示的谱面仍对应本次已经确定的演奏，修改会在下一次起播时应用。

点击“独立窗口 / 置顶”可放大观察；独立窗口与主窗口共享谱面视图和时间窗，也可取消“置顶显示”。播放时切回游戏接收输入。如果游戏的独占全屏遮住置顶窗口，可使用无边框窗口模式或将可视化窗口放到另一块屏幕。显示内容反映软件的键盘输出，不检测游戏是否收到按键或实际发声。

绘图在 Tk 主线程进行，播放线程只发布不可变状态快照。可见音符按键建立索引，滚动时只绘制当前时间窗内的音符，并复用 Canvas 图元。

## 项目结构

| 路径 | 作用 |
| --- | --- |
| `genshin_gui.py` | 主程序：GUI、解析报告、全局热键、标签管理和播放器接入。 |
| `midi_engine.py` | MIDI 起止事件与踏板解析、旋律/转调分析、音长模式、按键时间轴与播放器。 |
| `live_midi.py` | 实时 MIDI 音符／踏板状态、前台检测、输入队列与键盘输出。 |
| `usb_midi.py` | Windows WinMM MIDI 设备枚举、输入端口与消息解码。 |
| `performance_view.py` | 五线谱时值/长条谱、红色不可奏音符、时间轴浏览、21 键状态和短音提示。 |
| `song_memory.py` | 歌曲记忆的数据校验、手动/自动优先级和标签起点解析。 |
| `song_library.py` | 中英文曲名排序、添加/播放时间记录、旧曲库时间初始化。 |
| `songs/` | 曲库目录。GUI 只扫描这一层，不递归扫描子目录。 |
| `song_labels.json` | 每首歌的进度标签、演奏记忆、添加/播放时间，以及全局快捷键和排序设置。 |
| `启动.bat` | 请求管理员权限、安装 `mido` / `pydirectinput` / `pypinyin` 并启动 GUI。 |
| `原神演奏.spec` | PyInstaller 打包配置；生成请求管理员权限的无控制台程序。 |
| `dist/` | 已打包程序及发布文件。 |
| `archives/` | 清理旧版本时压缩保留的历史配置、源码备份与旧说明，不参与程序运行。 |
| `tests/` | MIDI 音长、同键冲突、暂停跳转、歌曲记忆、曲库排序、连续切歌、可视化状态和 Canvas 绘图回归测试，使用虚拟键盘，不发送真实按键。 |

`songs` 目录只保留放置歌曲的说明，不附带 MIDI 曲目。

## 运行环境

- Windows 10/11。
- 源码版在 Python 3.13 上验证，安装时需包含 Tkinter（官方 Windows Python 通常自带）；打包版无需安装 Python。
- Python 依赖：`mido`、`pydirectinput`、`pypinyin==0.55.0`（[拼音转换说明](https://pypinyin.readthedocs.io/zh-cn/master/usage.html)）。打包版已包含这些依赖。
- 能够使用键盘演奏的原神乐器。

管理员权限不是 MIDI 解析本身的要求，但当游戏以较高权限运行时，播放器也需要同等级权限才能稳定发送输入。`启动.bat` 和打包配置都已请求管理员权限。

## 使用方法

### 从源码启动

最简单的方式是双击 `启动.bat`。它会切换到项目目录、检查并安装依赖，然后执行：

```powershell
python genshin_gui.py
```

也可以手动安装依赖并启动：

```powershell
python -m pip install -r requirements.txt
python genshin_gui.py
```

### 使用打包版

从仓库的 **Releases** 下载 Windows ZIP，完整解压后运行 `原神演奏.exe`。程序包含四种音长模式、可点击和滚动的演奏可视化、三种曲库排序和 USB MIDI 实时演奏。整个程序目录需要一起保留，不能只复制 exe；程序依赖同目录的 `_internal` 和 `songs`。在本地自行打包时，默认输出为 `dist/原神演奏/原神演奏.exe`。

打包版使用 exe 同目录的 `song_labels.json` 和 `songs`，源码版使用项目根目录的对应文件，后续修改不会自动同步。发布包不提供个人配置；首次运行生成默认配置。升级已有安装时，保留自己的 `songs` 和 `song_labels.json`。

### 推荐操作流程

1. 将 MIDI 文件直接放入 `songs` 目录，点击“刷新曲库”。
2. 在曲目区选择排序方式，搜索或选择歌曲，点击“解析”。
3. 已有记忆的歌曲会自动恢复配置及起播点；新歌使用默认分析结果。试听前确认通道、主旋律音轨、转调和扫音检测结果。
4. 选择音长模式，按需要调整“只弹主旋律”“屏蔽扫音”“八度折叠”、转调量和速度；先关闭踏板试听，再单独比较踏板效果。
5. 在原神中打开乐器界面；需要边听边看时先打开“独立窗口 / 置顶”，再回到程序点击“播放”。
6. 在 5 秒倒计时内切回游戏并保持游戏为前台窗口。

切换歌曲时，推荐使用“停止 → 选择歌曲 → 解析 → 播放”。通道或音轨改变后程序会重新分析；其他演奏参数会在真正开始播放时重新生成发音序列。

对比四种音长模式时，先关闭踏板，用同一段音乐测试，再单独打开踏板比较。“和弦长音”适合观察伴奏和弦的持续与主旋律的短按，踏板只延长符合条件的和弦部分。新模式可能改变总时长和比例标签对应的乐句，满意后可移动标签并点击“手动记忆”。若出现异常，记录曲名、模式、转调、八度折叠、速度、踏板开关和曲中位置，便于复现。

## 曲库排序与时间记录

曲目区提供三种排序，选择会自动保存，下次启动继续使用：

| 排序 | 规则 |
| --- | --- |
| 首字母 A–Z | 中文按拼音、英文忽略大小写混合排序；忽略开头的空白、括号等符号。字母之后排列数字及其他字符开头的歌名。 |
| 添加时间 | 最近添加的歌曲在前。 |
| 播放时间 | 最近一次开始演奏的歌曲在前；尚无播放记录的歌曲在后。记录日期和时刻，不累计播放次数或播放时长。 |

时间相同时按曲名 A–Z 排序。排序栏下方显示**下拉框所选歌曲**的添加时间与最近播放时间，精确到秒，使用电脑本地时区。搜索结果遵循当前排序；切换排序或刷新曲库会尽量保留所选歌曲，也不会中断正在演奏的歌曲。

首次使用此版本时，旧曲库没有历史添加记录，会以 `songs` 中各文件的创建时间初始化（这是近似值，无法还原先前复制、移动的历史）。此后新歌曲使用程序首次扫描到它的时间；添加文件后点击“刷新曲库”即可记录。记录一旦保存便不会随再次刷新或文件修改而改变。旧版没有记录的播放时间显示“尚无记录”，不会从已有记忆推测播放日期。

倒计时结束、播放器成功启动时才更新最近播放时间；只解析、取消倒计时、没有可奏音符、暂停/继续、拖动进度或停止均不更新时间。重新起播、自动切歌和单曲循环的每次起播都会更新。标签、演奏记忆和这些时间仍按文件名关联，重命名文件会被视作另一首歌曲。

**连续播放的顺序**：起播时采用当时的曲库顺序，上一曲、下一曲和自动顺序播放共用这份顺序。“最近播放”列表会即时重排，但不会让正在连续播放的队列反复跳回刚播过的歌曲；顺序播放时，本轮开始后新加入的歌曲留到下一轮。主动切换排序会立即更新后续队列，当前歌曲继续演奏。停止后重新起播也会采用最新排序。搜索只筛选下拉框，不限制播放队列。

时间保存在 `song_labels.json` 的歌曲条目中：`added_at` 是添加时间，`last_played_at` 是最近起播时间；全局 `settings.song_sort` 保存排序方式。复制发布目录或备份时一并保留这份配置，就能保留这些记录。

## 全局快捷键与标签

快捷键输入框支持单键或组合键，例如 `F8`、`/`、`Num+`、`Ctrl+Alt+L`。为避免与演奏冲突，`QWERTYU`、`ASDFGHJ`、`ZXCVBNM` 这 21 个游戏琴键不能注册为软件快捷键。

首次运行的默认快捷键为：

| 操作 | 快捷键 |
| --- | --- |
| 插入标签 | `F8` |
| 上一曲 | `F6` |
| 播放/暂停 | `F7` |
| 停止 | `F9` |
| 下一曲 | `F10` |

已有安装会保留配置文件中保存的快捷键，可在界面内修改。快捷键可能被其他程序占用，注册失败时需要换键。

标签按歌曲文件名关联，并以总进度比例保存，而不是固定秒数，所以改变播放速度后仍能定位到相近的乐曲位置。标签支持跳转、改名、移动到当前进度和删除。

## 歌曲配置与起播记忆

每首歌独立保存：勾选的乐器通道、主旋律音轨（自动或指定音轨）、只弹主旋律、屏蔽扫音、八度折叠、音长模式、延音踏板开关、转调量、播放速度，以及起播位置。顺序播放、单曲循环和随机播放仍是全局播放模式，不随歌曲配置切换。

旧记忆缺少音长字段时按“固定短按、踏板关闭”恢复，以便保留原先效果；新歌默认“原谱音长、踏板关闭”。选择新模式后点击“手动记忆”，或实际开始播放一次，即可按原有记忆规则保存。音长模式与新的总时长可能改变比例标签对应的乐句位置，可按需要重新移动标签。

### 自动记忆

点击播放后，在倒计时结束、真正起播时，记录本次实际使用的配置和起点。倒计时期间拖动进度条或选择标签，会采用最后选定的起点；其他演奏参数仍使用启动倒计时时的配置。倒计时中点击谱面则取消自动起播，等待手动播放。取消倒计时或没有可演奏音符时不会覆盖原来的记忆。

- 点击一个标签后播放，会记住该标签的 ID；选中的起播标签显示为蓝色。
- 从拖动进度条的位置播放，会记住对应进度比例；未选择起点则从曲首开始。
- 记住的是“从哪里开始”，不是暂停、停止或结束时已经播放到的位置。
- 再次解析该歌曲、使用上一曲/下一曲、自动切歌或单曲循环时，均会恢复记忆配置与起播点。
- 标签改名不影响记忆；移动后会跟随新位置；删除后回退到该标签删除前的位置。

### 手动记忆（优先于自动记忆）

进度条下方的“歌曲记忆”区域有三个按钮：

| 按钮 | 行为 |
| --- | --- |
| 手动记忆 | 无需播放，立即保存当前演奏配置和所选起播点；再次点击可主动更新这份记忆。 |
| 恢复记忆 | 恢复该歌的手动记忆；没有手动记忆时恢复最近的自动记忆。播放中使用此按钮会先停止播放。 |
| 清除手动记忆 | 仅移除该歌的手动记忆，让最近的自动记忆重新成为默认；不会删除标签。点击“恢复记忆”或重新解析后应用。 |

例如，先选择“副歌”标签、调整速度并点击“手动记忆”。以后即使临时从曲首以其他速度播放，自动记录也不会覆盖手动记忆；下次解析仍恢复手动保存的速度与“副歌”起点。

播放过程中点击“手动记忆”，保存的仍是所选起播点，而不是滚动的播放进度。若要手动记住其他位置，先点击目标标签或拖动进度条，再点击“手动记忆”。

记忆与原有标签共同存放于 `song_labels.json`，在对应歌曲条目的 `playback_memory` 下分别保存 `manual` 和 `auto`。旧版仅有标签的文件可直接读取，不需要迁移。没有记忆的新歌曲会恢复默认演奏参数，不沿用上一首歌的配置。

## MIDI 选择与常见问题

### 解析成功但听起来很乱

减少勾选的乐器通道，尝试“只弹主旋律”，并手动指定主旋律音轨。普通钢琴 MIDI 经常同时包含旋律、伴奏、装饰音和控制轨，全部映射到 21 键会显得拥挤。

### 大量音符没有播放

原神乐器只有 21 个自然音。超出音域的音可通过八度折叠处理，但升降音仍会被过滤。先使用建议转调；效果仍差时，应换用原神适配 MIDI 或在编曲软件中预先转调、简化。

### 和弦或快速段落漏音

游戏输入频率、系统负载和 MIDI 密度都会影响结果。可以降低播放速度、减少通道，或只保留主旋律。同键间隔不足时会缩短前音；原谱长音听起来过密时，可比较“旋律长音”模式并关闭延音踏板。

### 热键不生效

检查快捷键是否被其他程序占用，以及播放器与游戏的权限等级是否一致。不要使用 21 个游戏琴键作为控制热键。

### 新增歌曲没有出现

确认扩展名是 `.mid` 或 `.midi`，文件直接位于 `songs` 目录而不是子目录，然后点击“刷新曲库”。

## 打包

安装 PyInstaller 后可使用现有 spec：

```powershell
python -m pip install -r requirements-build.txt
pyinstaller 原神演奏.spec
```

当前 spec 只打包 Python 程序及依赖，没有在 `datas` 中自动加入曲库与配置。发布前在 `原神演奏.exe` 同级创建 `songs` 目录并放入 `songs/README.md`，同时复制本说明；不要将个人 MIDI 或 `song_labels.json` 放进公开发布包。自己升级使用时，可保留原来的歌曲和配置。

PyInstaller 的构建缓存可以重新生成；本项目的 `build` 中也可能保留同步脚本、校验清单和升级前备份，清理时应只删除明确可重新生成的缓存。

## 使用提醒

本项目属于键盘输入自动化工具，不是原神官方功能。请自行判断并遵守游戏规则，只在合适的场景中使用。不同 MIDI 的编曲差异很大，在对外演奏前建议先自行试听和调整。
